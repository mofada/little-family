# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

一个真实家庭内部的亲属群体，由家庭所有者作为**唯一维护者**统一录入和校对成员与生日；其他亲属受邀加入后，可以关联到自己、查看家庭资料、退出家庭，但不能增删改成员或发出邀请。

使用发生在微信内、碎片时间：想起某位亲戚的生日、被问到"该叫二舅还是表舅"、生日当天被提醒。维护者是替全家"记事"的那个人，录入动作需要短、可中断、可回头补。

## Product Purpose

小家记是一个私有家庭空间，把**家庭关系档案**、**成员生日**和**协作维护**收在一处。

它存在的理由是：亲属称呼和农历/公历生日散落在长辈记忆、通讯录备注和聊天记录里，既会记错也会忘。产品成功意味着——亲属不再记错生日，不必手填称呼，家庭资料有一个全家都认的可信来源。

## Positioning

**生日记得住，祝福写得出来。**

- 农历与公历都按换算后的下一次公历日期排序，不会被"农历生日"的换算问题绊住；
- 北京时间 08:00 通过微信一次性订阅消息把当天生日推到用户手机上，而不是要求用户主动查日历；
- 生日祝福由 AI 按成员关系生成、可直接复制发送；
- 亲属称呼按"当前登录用户 → 目标成员"的视角自动推导并缓存，而不是让每个人手填一份。

通讯录和普通日历能做到"存一个日期"，做不到"换算 + 到点提醒 + 替你写祝福 + 替你想清楚称呼"这一串。

## Operating Context

- 主要在**微信小程序**内使用；另有 Web H5 作为次要形态，两者共享同一份 API、家庭快照与权限规则。
- 服务端为自托管 Node.js + SQLite，不依赖第三方后端；登录依赖微信 OpenID/UnionID，Web 端支持一次性登录码与微信开放平台扫码。
- 家庭通过邀请码加入，多家庭并存，每条家庭数据按 `family_id` 隔离。
- 生日提醒依赖用户逐次授权的一次性订阅消息：每次授权只能用一次，发送成功后需再次订阅。
- 时间基准为北京时间；提醒任务每分钟检查一次，在 08:00–08:59 内为当天首次运行发送。

## Capabilities and Constraints

已确认的能力：

- 小程序主导航为五个 Tab：首页、图谱、时间轴、生日、我的；另有家庭管理、邀请、成员编辑等二级页面。
- 成员**仅姓名必填**，性别、出生年份、完整生日可选；每人最多关联两位父母和一位配偶。
- 成员之间的称呼由 AI 生成并写入 `kinship_labels` 缓存；普通列表、生日页与快照查询不会在缓存缺失时自动调用 AI，需用户在小程序生日管理页显式点击"刷新称呼"。
- 成员或关系变更后会清空该家庭称呼缓存，需要手动刷新重新生成。
- AI 祝福生成失败或未配置时，降级为复制原始祝福提示词。
- 邀请码、网页一次性登录码（单次使用、5 分钟过期）、PC 扫码登录（OAuth state 单次使用）。

需要未来工作保留的约束：

- **只有家庭所有者能增删改成员和发出邀请**；其他成员只能加入、关联自己或退出。权限由 API 重新校验，不以客户端角色值代替判断——这是已确认的产品真相，不是待修的实现缺陷。
- AppSecret 只允许出现在 API 的 `.env`；登录令牌只存哈希；生产环境禁止开启开发登录。
- 不能硬编码可由成员数据推导的统计值（成员总数、今日/近期生日等）。
- 小程序依赖独立安装（微信"构建 npm"要求），不参与根 workspace 依赖提升。

明确未决的产品事实：

- Web 端的投入优先级为"视情况更新"，不是当前承诺；不做原生 iOS/Android。
- 称呼刷新目前是手动的，是否改为关系变更后自动重建缓存，尚未决定。

## Brand Commitments

- 名称：**小家记**（Little Family），文案统一为简体中文，语气是家常、克制、不煽情的"家里人说话"。
- 产品不宣称社交属性、不做公开主页，隐私是品牌承诺的一部分：家庭数据仅对受邀成员可见。

## Evidence on Hand

- 可用于设计验证的素材：真机截图、脱敏后的真实成员数据（使用时不得提交真实姓名、真实生日或任何可识别个人的资料）。
- 缺失且不得虚构：用户评价、媒体报道、客户案例、付费与转化数据。当前没有任何对外可引用的社会证明，界面与文案中不应出现臆造的推荐语或使用量。

## Product Principles

1. **关系一次录入，处处复用。** 称呼、图谱、时间轴、生日都从同一份成员关系推导，不在各页面各自维护副本。
2. **谁都能看，只有维护者能改。** 权限边界落在 API，界面上要让人一眼看出"我能做什么、不能做什么"，而不是点了才失败。
3. **记得住比记得全重要。** 生日和称呼是核心，其余字段允许留空；不为了数据完整度打断录入。
4. **AI 是增强，不是依赖。** 任何 AI 环节都必须有可用的降级路径，断网、未配置或调用失败时产品仍然完整。
5. **真实家庭数据不进仓库。** 脱敏、最小化传输，是产品承诺而非工程选项。

## Accessibility & Inclusion

未确立具体无障碍标准。已知约束：用户可见文案统一简体中文，字号与对比度需兼容微信系统字体缩放；生日与称呼信息以文字为主，不依赖颜色单独传达状态。
